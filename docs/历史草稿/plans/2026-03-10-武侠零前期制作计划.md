# 武侠零前期制作计划

> **给 Claude：** 执行本计划时，必须使用 `superpowers:executing-plans` 按任务逐步推进。

**目标：** 把已经确认的《武侠零》概念设计，转化为一套可直接指导原型制作、叙事细化与范围控制的前期制作文档包。

**整体思路：** 在进入任何引擎原型之前，先把战斗支柱、房间分类、章节节奏、角色动机与垂直切片范围固定成独立文档，确保后续原型验证有明确边界，不会一边做一边漂。

**技术栈：** 当前工作区中的 Markdown 文档；必要时可补充 Mermaid 图，但暂不依赖任何引擎或代码仓库。

---

### 任务 1：产出一页式高概念文档

**文件：**
- 创建：`docs/game/高概念.md`
- 参考：`docs/plans/2026-03-10-武侠零设计初稿.md`

**步骤 1：写核心卖点**

用一页内容说清楚项目幻想、类型、时长、参考体感和最重要的 3 个差异点。

**步骤 2：补充目标用户与体验承诺**

明确游戏是为谁做的、承诺什么体验、又刻意不做什么。

**步骤 3：对照设计初稿做一致性检查**

确认文档仍然体现：
- 约 5 小时核心流程
- 高速清房战斗
- 复杂人性下的复仇叙事

**步骤 4：做一次删减**

删掉任何会诱发范围失控的空泛愿景和未来功能。

**步骤 5：提交**

如果以后初始化为 git 仓库：

```bash
git add docs/game/高概念.md docs/plans/2026-03-10-武侠零设计初稿.md
git commit -m "docs: 补充武侠零高概念"
```

### 任务 2：定义战斗支柱文档

**文件：**
- 创建：`docs/game/战斗支柱.md`
- 参考：`docs/plans/2026-03-10-武侠零设计初稿.md`

**步骤 1：写清三个核心动词**

明确 `切入`、`破局`、`收刀` 分别意味着什么，以及它们的失败状态是什么。

**步骤 2：锁定玩家能力集合**

记录基础移动、刀术动作、`燃脉`、`断息`、`影踏` 的功能边界，并写清楚每项能力“不应该变成什么”。

**步骤 3：补充调参与节奏目标**

写明房间清除时长、死亡预期、能力使用频率，以及章节级的教学节奏。

**步骤 4：加入坏战斗自检清单**

列出原型跑偏的典型征兆，例如：
- 敌人太肉
- 正面莽就能过
- 房间读局太慢

**步骤 5：提交**

```bash
git add docs/game/战斗支柱.md
git commit -m "docs: 定义战斗支柱"
```

### 任务 3：建立房间与敌人矩阵

**文件：**
- 创建：`docs/game/房间敌人矩阵.md`
- 参考：`docs/plans/2026-03-10-武侠零设计初稿.md`

**步骤 1：列出核心房间原型**

至少包含长廊、庭院、楼阁、地牢、宴厅、追逐房、守关房。

**步骤 2：给每类房间匹配压力来源**

为每种房型写清：
- 第一优先威胁是谁
- 预期路线是什么
- 哪些敌人组合会逼迫玩家做选择

**步骤 3：写难度递增规则**

说明房间从第一章到终章如何升级，但不靠无脑加怪或加血。

**步骤 4：补防重复检查**

为每类房间标记哪些变量必须变化，避免玩家感觉自己一直在做同一道题。

**步骤 5：提交**

```bash
git add docs/game/房间敌人矩阵.md
git commit -m "docs: 补充房间敌人矩阵"
```

### 任务 4：扩展章节节拍表

**文件：**
- 创建：`docs/story/章节节拍表.md`
- 参考：`docs/plans/2026-03-10-武侠零设计初稿.md`

**步骤 1：拆出每章节拍**

对 7 个章节分别写清：
- 章节目标
- 新增战斗变化
- 关键情绪转折
- 章末揭示

**步骤 2：放置嵌入式剧情演出**

明确短演出放在哪些节点：
- 开场短戏
- 闪回插叙
- Boss 对峙
- 战后静场

**步骤 3：做叙事节奏检查**

确认没有哪一章连续剧情过多，也没有哪一章长时间只有战斗没有呼吸。

**步骤 4：补章节时长目标**

为每章估算目标分钟数，保证整体落在 5 小时附近。

**步骤 5：提交**

```bash
git add docs/story/章节节拍表.md
git commit -m "docs: 补充章节节拍表"
```

### 任务 5：撰写关键角色设定包

**文件：**
- 创建：`docs/story/关键角色设定.md`
- 参考：`docs/plans/2026-03-10-武侠零设计初稿.md`

**步骤 1：为主角与关键目标写人物卡**

每张人物卡至少包含：
- 对外身份
- 内在伤口
- 曾做出的妥协
- 玩家为何能理解他
- 玩家为何仍必须与他对决

**步骤 2：补关系张力说明**

为每组关键关系写一段简短说明，突出冲突根源。

**步骤 3：写对白样张**

给每个主要角色写 3 到 5 句能体现其声音差异的对白。

**步骤 4：检查复杂人性是否成立**

确保重要人物没有谁像纯圣人，也没有谁像纯怪物。

**步骤 5：提交**

```bash
git add docs/story/关键角色设定.md
git commit -m "docs: 补充关键角色设定"
```

### 任务 6：定义垂直切片范围

**文件：**
- 创建：`docs/production/垂直切片范围.md`
- 参考：`docs/game/战斗支柱.md`
- 参考：`docs/game/房间敌人矩阵.md`
- 参考：`docs/story/章节节拍表.md`

**步骤 1：选定切片片段**

选择一个章节片段，至少能展示：
- 一个标准战斗房
- 一个特殊房
- 一个精英或 Boss 遭遇
- 一段嵌入式剧情演出

**步骤 2：写成功标准**

明确切片必须证明：
- 战斗可读性
- 移动手感
- 房间重开速度
- 美术与叙事基调一致性

**步骤 3：划定不做范围**

剔除所有当前验证点并不需要的功能，保护切片体量。

**步骤 4：附加试玩问题清单**

准备 8 到 10 个试玩问题，集中验证手感、清晰度、难度和叙事气质。

**步骤 5：提交**

```bash
git add docs/production/垂直切片范围.md
git commit -m "docs: 定义垂直切片范围"
```

### 任务 7：把文档转成原型待办清单

**文件：**
- 创建：`docs/production/原型待办清单.md`
- 参考：`docs/production/垂直切片范围.md`
- 参考：`docs/game/战斗支柱.md`

**步骤 1：列出原型阶段的 Epic**

至少包括：
- 玩家控制器
- 刀术战斗
- 特殊能力
- 敌人 AI
- 房间重开流程
- 剧情触发系统

**步骤 2：把每个 Epic 拆成很小的动作项**

确保每项都能在 2 到 5 分钟级别内执行，不隐藏额外规划成本。

**步骤 3：给每个 Epic 配上验证标准**

写清楚完成后靠什么判断它真的可用。

**步骤 4：按依赖顺序排序**

目标是尽快得到第一版可玩的核心循环。

**步骤 5：提交**

```bash
git add docs/production/原型待办清单.md
git commit -m "docs: 补充原型待办清单"
```

## 备注

- 当前工作区仍是文档工作区，还不是 git 仓库。
- 因为尚未选定引擎、代码结构和测试框架，所以此阶段的验证主要是设计审阅与范围检查，而不是自动化测试。
- 一旦后续选定引擎并建立仓库，就应把这份计划改写为引擎对应的实现计划，补齐准确文件路径、测试方式和执行命令。
